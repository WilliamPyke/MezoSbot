You are building the first MVP for a Slice Ads-powered PvP skill arcade on Mezo Network.

Project name:
Slice Arcade PvP MVP

Core concept:
Build a web-first head-to-head PvP skill game where two players stake the same amount of BTC, play the same deterministic block puzzle challenge, and the highest server-validated score wins the pot after platform rake.

This is player vs player.
The platform is not the opponent.
The platform does not fund prizes.
The platform does not take directional risk on match outcomes.
The platform earns revenue from rake and later from Slice Ads.

Primary economy:
- Player A stakes BTC.
- Player B stakes BTC.
- Both stakes form the gross pot.
- Platform takes a configurable rake from the gross pot.
- Winner receives gross pot minus rake.
- Platform keeps the rake.
- Slice Ads are shown around the experience as an additional monetization layer.
- Slice Ads do not fund payouts.
- Slice Ads do not modify gameplay.
- Slice Ads do not modify match results.

Default MVP economics:
- platformRakeBps = 1000
- 1000 bps = 10%
- grossPotSats = playerAStakeSats + playerBStakeSats
- rakeSats = floor(grossPotSats * platformRakeBps / 10000)
- winnerPayoutSats = grossPotSats - rakeSats

Example:
- Player A stake: 1,000 sats
- Player B stake: 1,000 sats
- Gross pot: 2,000 sats
- Rake: 200 sats
- Winner payout: 1,800 sats
- Platform revenue: 200 sats

- Do not build random outcomes that determine winners.

Game rules:

Board:
- 9x9 grid
- Grid cells can be empty, normal block, or multiplier block
- 3x3 sub-squares count as clearable zones
- Rows, columns, and 3x3 squares clear when fully occupied

Turn / level flow:
- Player receives 3 pieces per level
- Player can place the 3 pieces in any order
- If no remaining piece can be placed, the game ends
- After all 3 are placed, advance to next level and deal 3 more pieces
- Maximum 12 levels for MVP
- Add a 3-minute timer for each match in the UI
- Timer should be enforced server-side if feasible; otherwise structure code with a TODO for server-side enforcement

Scoring:
- +10 per placed cell
- +25 bonus per cleared row
- +25 bonus per cleared column
- +25 bonus per cleared 3x3 square
- Combo bonus: if multiple zones clear from one placement, add +25 per extra cleared zone
- Multiplier starts at 1x
- If a placement clears a multiplier block, increase multiplier by +1x
- All future points are multiplied by current multiplier
- Cap multiplier at 5x for MVP

Important scoring detail:
Only increase multiplier when a multiplier block is actually cleared through a row, column, or 3x3 square clear.
Do not increase multiplier merely because a multiplier cell was placed.

Piece system:
The game needs a flexible shape definition system that supports:
- connected pieces
- disconnected pieces
- diagonal-only pieces
- single-cell pieces
- sparse patterns inside a bounding box
- multiplier cells inside any piece

Represent every piece as normalized cell coordinates, not as a string grid that assumes connectivity.

Use these types or equivalent:

type PieceCell = {
  x: number
  y: number
  kind: "normal" | "multiplier"
}

type PieceDefinition = {
  id: string
  label: string
  cells: PieceCell[]
  allowRotation: boolean
  weight: number
  minLevel?: number
  maxLevel?: number
}

Coordinates are relative to the piece origin.

Examples:

single:
cells = [{ x: 0, y: 0, kind: "normal" }]

two_horizontal:
cells = [
  { x: 0, y: 0, kind: "normal" },
  { x: 1, y: 0, kind: "normal" }
]

diagonal_2:
cells = [
  { x: 0, y: 0, kind: "normal" },
  { x: 1, y: 1, kind: "normal" }
]

diagonal_3:

  { x: 1, y: 1, kind: "normal" },
  { x: 2, y: 2, kind: "normal" }
]

anti_diagonal_3:

  { x: 2, y: 0, kind: "normal" },
  { x: 1, y: 1, kind: "normal" },
  { x: 0, y: 2, kind: "normal" }

  { x: 0, y: 1, kind: "normal" },
  { x: 0, y: 2, kind: "normal" },

  { x: 2, y: 2, kind: "normal" }
]

  { x: 1, y: 0, kind: "normal" },
  { x: 0, y: 1, kind: "normal" },
  { x: 1, y: 1, kind: "normal" },
  { x: 2, y: 1, kind: "normal" },
  { x: 1, y: 2, kind: "normal" }
]

Multiplier variants:
Any generated piece may include exactly one multiplier cell.
The multiplier cell should be marked as kind: "multiplier".
Multiplier pieces should be visually orange for the multiplier cell only.

A piece is placeable if all of its cells fit inside the board and none overlap occupied cells.
Connectivity does not matter.
Clearing still only applies to full rows, full columns, and full 3x3 squares.
